Engineering Dashboard — Migration to Gentari

Briefing for IT: what it is, how it is built, run and secured, and what we need from you

1What it is

Next.js 14React 18TypeScriptTailwindNode 22Supabase (Postgres + Auth)
  • Internal engineering web app: 6 calculators (gas LCOE, multigas converter, H₂ blend, pipeline sizing, NH₃ cracker, NH₃ storage)
  • Login, roles (admin / user), user management, login and activity audit
  • No custom API server; calculators run in the browser — engineering inputs are never sent to a server

2Data & access control

  • 3 tables only: profiles, login_logs, activity_logs
  • Holds user email, name, role, IP, user agent, login times — no engineering or commercial data
  • Server-side guards on every page; row-level security on all tables
  • No public sign-up — admins create accounts; every login and admin action is audited

3How we develop

  • Source in Git; database schema in versioned SQL migrations
  • Local setup: npm install → copy .env.example → npm run dev
  • Checks today: lint and typecheck
  • Proposed flow: feature branch → pull request → review → merge to main → auto-deploy, with separate dev / staging / prod

4How we maintain

  • Small footprint: 5 runtime dependencies
  • Proposed: Dependabot / Renovate + npm audit in CI
  • New calculator = one entry in the module registry (low effort)
  • Named primary owner + backup, and a short runbook

5Security

  • Secrets only in environment variables, never in Git; service-role key is server-only
  • Passwords and sessions handled by Supabase Auth — no custom crypto
  • RLS enabled; privileged DB functions hardened (migration 0003)
  • Proposed: SSO via Gentari identity provider + MFA
  • Proposed: security headers / CSP, rate limiting, dependency scanning
  • Proposed: security review by IT before go-live

6Known gaps — and the fix (we raise these first)

GapFix
No Dockerfile / CI pipelineAdd standalone build + Dockerfile; CI running lint, typecheck, build
No automated testsAdd tests for auth and admin actions first, then calculators
Next.js 14.2 is behind currentUpgrade plan + vulnerability scan before go-live
No security headers, CSP or rate limitingConfigure in app and/or at the reverse proxy
Calculators load Google Fonts from the internetSelf-host fonts for the internal network
Vercel / personal identifiers in repo and docsClean before importing into Gentari Git

7What we need from IT

  • Hosting: container platform or Gentari standard
  • Database decision: Gentari-owned Supabase tenant, or Postgres + auth replacement (largest decision)
  • Identity: SSO / MFA integration
  • Network: domain, TLS certificate, reverse proxy / WAF
  • Platform: secrets store, logging, backup and retention policy
  • Delivery: Git repository and CI/CD pipeline; security review slot

Source: repository review of Dashboard/ (Next.js app, Supabase migrations 0001–0003). Items marked “Proposed” are not yet in place.
