Supabase

Managed Postgres + Auth
Auth
passwords, sessions, tokens
↕
profiles
role, name, disabled
RLS: self or admin
↕
login_logs
IP, user agent, login/logout time
RLS: admin read only
↕
activity_logs
action, target, metadata
RLS: admin read only
 
No engineering data stored

Login path

  • Form → login action → Supabase Auth → profile check
  • Disabled account: signed out immediately
  • Success: login_logs + activity_logs row, then redirect by role

Every page request

  • Layout calls requireUser() or requireAdmin()
  • Not signed in → /login; wrong role → /unauthorized
  • If Supabase is unreachable, user is treated as signed out
